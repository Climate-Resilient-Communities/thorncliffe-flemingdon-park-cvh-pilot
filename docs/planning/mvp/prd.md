# Community Virtual Hub (CVH) — MVP PRD

**Status: parked.** Work is focused on the pilot. This document will be completed after the pilot, using its measures (Pilot PRD Section 9) to set targets.

## 1. Baseline

The MVP is specified by PRD v2 (`docs/CVH - PRD v2.docx`) as amended by the decisions below. The combined v3 draft that phased every v2 requirement (`docs/planning/mvp/prd-v3-combined-draft.md`) is the starting point for the rewrite.

The MVP includes everything the pilot delivers (Pilot PRD Section 7) plus every capability listed in Pilot PRD Section 6.3.

## 2. Decisions already made for the MVP

| Topic | Decision |
|---|---|
| Client | Native iOS and Android apps, plus web |
| Channels | Push, SMS, email; WhatsApp Business API out, sharing to WhatsApp in; voice later |
| Translation | Alert templates and interface text checked by people in all 15 languages; audio versions; Cohere for other content, labelled |
| Official alerts | Relayed from City, ECCC and Alert Ready, with a person confirming each relay |
| Broadcast safety | Two-person approval, corrections on every original channel, drill separation (as in the pilot) |
| Roles | Admin (Hub staff and IT), Coordinator, Director, Partner organization (same cluster), Ambassador |
| Data ownership | Community owns the data under the terms of service |
| Privacy law | PIPEDA |
| Data residency | Canada only, including SMS and messaging |
| Retention | 3 to 7 years for reporting and audit records |
| Reliability | Uptime, delivery time and scale targets to be set from pilot data |
| SMS | Budget and provider scoped for MVP scale |
| Safeguarding | Ambassador vetting, device controls, consent through a trusted helper, minimum age |
| Buildings | Master list maintained by the Hub with last-updated dates |

## 3. Open before the MVP

- Hub operating hours and approval timeouts per disruption type (process not yet trained)
- An overnight path for fire, evacuation and "Other" posts when no second approver is awake (accepted as pilot risk R-11)
- Staff sign-in by email with self-service password reset (the pilot uses Admin-set usernames and Admin resets)
- Official alert sources, terms and intake method
- Canadian SMS provider and sender type
- Extension beyond the 43 pilot buildings (60 further buildings in the register)
- Ambassador incentives, role boundaries and training
- Partner and building management engagement and data-sharing agreements
- Hub calendar connection and maintenance
- Post-pilot funding
- Whether winter storms need a seventh guide and playbook
- When service tagging and partner confirmation of listings come into scope
- All open validation findings that the pilot does not resolve (see `docs/planning/validation/validation-report.md`)
